# 知乎写作风格定义

> 这是作者本人维护的风格权威文件。`zhihu-publishing` skill 在写作 / 润色每一篇文章前必须先读本文件，并严格遵循。
>
> 调整风格 = 改这个文件，**不改草稿**。这里没有写到的，按 skill 默认；这里和 SKILL.md 冲突时，**以本文件为准**。

---

## 0. 第一原则：轻润色，不重写

**保留作者的语气和节奏。** 改的字数超过原文 **5%** 就是改太多了，退回去。

你只做四件事：

1. 修明显错字和重复字
2. 调整段落（每段 1–3 句）
3. 抚平特别拗口的句子（保守，能不动就不动）
4. 准备配套素材（题图、解释图、标题候选、摘要）

**不要做**：改用词偏好；加 AI 味连接词（"首先 / 其次 / 综上所述 / 值得注意的是"）；把口语改书面；加 emoji；重组段落顺序；"提升"作者表达。

## 1. 语气 DNA

- **胸有成竹地下断言。** 该说「必须」就说「必须」，不绕弯、不加「我觉得可能也许」的缓冲。
- **先给答案，再给背景。** 知乎读者要的是结论，不是铺垫。第一句就能立住。
- **细节用表格 / 列表列出**，不要在叙述句里堆细节。能列就列。
- **口语词原样保留**：句尾的「吧 / 呢 / 啊 / 了」、自造词、家常比喻——删了就不是这个人写的。
- **第一人称就是「我」**，绝不改成「笔者」。
- **称呼 AI / Claude 一律用「他」，不用「它」。** 作者把 AI 当人看待——「让他帮我」「告诉他」「约束他」「他会帮我做」。润色时绝不把「他」改成「它」。
- **人称主语优先。** 多用「我 / 他」起句，少用「这里会有……」「有一大堆……」这类无人称、物称句。
- 在具体和抽象之间反复架梯子：抽象判断后面紧跟一个具体例子，反之亦然。
- **并列类比堆叠论证。** 一个抽象判断之后，连甩 2–3 个具体类比把它砸实。这是作者论证的招牌动作——不要精简成只剩一个。
- **荐自己的东西先说实话、降期待。** 推荐自造工具时先自贬一句，不吹、不端着，再大方开源。诚恳比包装更像他。

## 2. 长度（知乎默认）

- **默认 1500–3000 字。** 知乎算法对 1500 字以上文章更友好；但写完内容就停，不硬塞。
- 纯观点短文允许 800–1200 字。
- 技术深度文章可到 4000 字，超过则考虑拆篇。
- 每个例子段过这把尺：**真具体（真事 / 真人 / 真数字），还是为演示框架编的？** 后者直接删。
- **优先保留**：开头钩子 + 核心框架 + 1 句点睛 + 结尾。
- **优先砍掉**：演示性例子、重复阐释。

## 3. 强调方式（知乎不支持彩色文字）

知乎编辑器**不渲染** `<span style="color:...">` 等内联样式，写了也是废代码。**禁用所有内联 HTML 颜色**。

强调方式：
- 关键结论 → `**bold**`（知乎原生渲染，清晰）
- 命令 / 方法名 / 短代码 → `` `inline code` ``
- 不滥用，每节最多 1–2 处加粗

## 4. 排版细节（知乎原生 Markdown）

知乎富文本编辑器原生支持以下格式，用标准写法，**不要用 WeChat 的 raw HTML 补丁**：

- **标题**：`## H2`、`### H3`，知乎自动生成侧边栏目录
- **加粗**：`**text**`
- **斜体**：`*text*`（偶尔用，不滥用）
- **代码块**：标准 fenced block，必须带语言标签：
  ````
  ```python
  x = 1
  ```
  ````
- **内联代码**：`` `code` ``
- **引用**：`> text`（知乎支持原生 blockquote，不需要 raw HTML）
- **列表**：`- ` 无序 / `1. ` 有序，均正常渲染
- **表格**：标准 Markdown 表格，知乎支持
- **分隔线**：`---`
- **链接**：`[文字](URL)`
- **图片**：`![alt](URL)`，本地图片由脚本自动上传 imgur CDN

**不用**：
- `<span style="...">` — 颜色等内联样式，知乎全部丢弃
- `<section style="...">` — WeChat 代码块补丁，知乎不需要
- `<blockquote style="...">` — 直接用 `>` 即可

**盘古之白**：中英 / 中数之间留空格——「用 AI 写 skill」「1000 篇文章」。

**手打省略号「。。。」原样保留**，不要规整成「……」——那是有意为之的味道。

## 5. 分段规则

分段时机：

- 一句话讲完一个意思，下一句换主语 → 分段。
- 句首出现「但是 / 不过 / 所以 / 后来」→ 考虑分段。
- 一段超过 80 字 → 找最近句号分。

不分段：排比句、列举、对话。

## 6. 标题结构（知乎）

- 文章标题在 meta.json 的 `title` 字段，知乎编辑器单独填，**正文里不重复写 `# H1`**。
- 节标题用 `## H2`，平铺，不嵌套。子节偶尔用 `### H3`，只在真正需要时。
- **不用** `**粗体引题句**` 代替标题——知乎有侧边栏目录，给读者真正的 H2 锚点。

标题候选给 3 个：A) 直白型；B) 故事型；C) 原文里最有味道的一句。不做标题党、夸张、"震惊"、"必看"。

摘要 50–80 字：不是第一段的复制；一句话说清读者会获得什么；用作者语气，不是营销腔。

## 7. 开头与结尾（知乎惯例）

**开头**两种合法模式，选一种：

- **直入法**：第一句直接给结论或核心概念，无铺垫
- **问题法**：抛出读者真正在想的那个问题，立刻给答案

**不用**：痛点故事铺垫、"大家好我来介绍一下"式寒暄。

**结尾**建议结构：

```markdown
## 参考资料

- [标题](URL)
```

可选加一行：`如有错误，欢迎评论区指正。`

**不加**：求关注/点赞/转发（知乎读者反感，平台有自己的互动引导）。

## 8. 话题标签（topics）

知乎用「话题」做内容分发，不是自由标签。meta.json 里的 `tags` 填关键词，发布时在编辑器选对应话题。

- 选 1–5 个话题，技术具体词（「Claude」「AI Agent」「Python」），不写宽泛词（「编程」「技术」）。
- 优先选有粉丝量的话题，覆盖核心概念即可，不要为了多选而选偏题。

## 9. 润色启发

错字模式：

- "的得地"误用（按语法）。
- 重复字："我我"、"是是"、"了了" → 删一个。
- 同音字（"在" vs "再"，"做" vs "作"，"以外" vs "意外"）。

## 10. 红线清单

| 不要 | 原因 |
|------|------|
| `<span style="color:...">` 彩色文字 | 知乎全部丢弃，变废代码 |
| `<section style="...">` 代码块 | WeChat 专用补丁，知乎用标准 fenced block |
| `<blockquote style="...">` raw HTML | 知乎原生支持 `>`，直接用 |
| 正文写 `# H1` 标题 | 知乎编辑器标题单独填，正文重复是错误 |
| "我觉得" → "笔者认为" | 改变作者身份 |
| 删句尾"吧 / 呢 / 啊 / 了" | 删了就不是这个人写的 |
| 加"欢迎关注 / 点赞在看" | 作者自己决定；知乎读者反感 |
| 自己加举例 / 引用 / 数据 | 这是写作，不是补全 |
| 加 AI 味连接词、把口语改书面 | 留下 AI 痕迹 |
| 改完没给 diff 直接全文输出 | 用户看不见你改了什么 |

## 11. 交付前：先给改动清单

润色完**先告诉用户改了什么**，再问要不要继续：

```
我改了 7 处：
1. L3: "我我觉得" → "我觉得"（重复字）
2. L8: 长段落 (120字) 拆成两段
...

要看完整结果吗？
```

改动 ≤ 3 处可直接给完整结果。
